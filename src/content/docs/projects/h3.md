## 是什么

h3 是一个把 HTTP 请求收成 `H3Event`、再用一层层 handler 决定回什么的最小框架。日常类比：它造的是车间里的工件卡，不是大门。卡上写着方法、路径和 Node `req`/`res`；谁来开门听端口，要另找 [[listhen]] 或自己 `http.createServer`。

你写：

```ts
import { createApp, createRouter, eventHandler, toNodeListener } from "h3"
import { listen } from "listhen"

const router = createRouter()
router.get("/hi", eventHandler(() => ({ ok: true })))

const app = createApp()
app.use(router)
await listen(toNodeListener(app))
```

固定 1.15.11 里，`app.use` 只往 stack 推 layer；`listen` 吃的是 Node `RequestListener`。把 `App` 直接塞给 listhen 对不上类型。

## 为什么重要

不看这层分工，下面几件事会对不上号：

- 为什么 Nuxt / Nitro 文档里到处是 h3，但它自己并不 `listen(3000)`
- 为什么 `createRouter()` 默认漏掉一条路由不会立刻 404，还能让后面的 layer 接着试
- 为什么 `return "hello"` 的 Content-Type 是 HTML，不是纯文本
- 为什么 npm `latest` 已经是 2.x RC，而 listhen 1.10.1 仍声明 `h3@^1.15.11`

## 核心要点

请求链可以拆成五步：

1. **入口适配**：`toNodeListener(app)` 新建 `H3Event`，调 `app.handler`。异常走 `createError` → 可选 `onError` → `sendError` 的 JSON。`toWebHandler` 标 experimental，内部仍用 `node-mock-http` 假 Node 对象。

2. **layer stack**：`createAppEventHandler` 先解码路径（只解 path、保住 query，并把 `%25` 护住以免二次解码），再按注册顺序匹配前缀和可选 `match`。

3. **返回值合同**：handler 返回非 `undefined` 就发送；`undefined` 且 `event.handled` 则停；否则下一层。全未处理抛 404。字符串按 HTML MIME，对象/布尔/数字走 JSON，`null` 是 204。

4. **路由器默认不抢占**：`radix3` 先查 method 再 `all`，再反向扫被同 path 阴影挡住的 method。未命中时默认 `return`，让 app 试下一层；`preemptive: true` 才抛 404/405。

5. **读 body 有方法门**：`readRawBody` / `readBody` 只允许 PATCH/POST/PUT/DELETE。JSON 用 `destr`；`application/x-www-form-urlencoded` 也会被解析。

## 实践示例

### 案例 1：h3 管事件，listhen 管听端口

```ts
import { createApp, eventHandler, toNodeListener } from "h3"
import { listen } from "listhen"

const app = createApp()
app.use("/health", eventHandler(() => "ok"))
await listen(toNodeListener(app), { port: 3000 })
```

`listen` 的第一参数类型是 Node `RequestListener`。这是本轮 HTTP-listen 配对的稳定接缝：h3 出 listener，listhen 开 socket、选端口、印 URL。

### 案例 2：默认 router 不会拦住后面的 layer

```ts
const api = createRouter()
api.get("/users", eventHandler(() => [{ id: 1 }]))

const pages = createRouter()
pages.get("/**", eventHandler(() => "<h1>app</h1>"))

createApp().use("/api", api).use(pages)
```

`GET /api/missing` 在默认（非 preemptive）router 上返回 `undefined`，控制权回到 app，后面的 `pages` 仍有机会。旧印象里“路由表就是终点”只在 `preemptive: true` 时成立。

### 案例 3：字符串和对象不是同一种响应

```ts
router.get("/text", eventHandler(() => "plain?"))
router.get("/json", eventHandler(() => ({ plain: false })))
router.get("/empty", eventHandler(() => null))
```

固定 `handleHandlerResponse`：字符串走 `text/html`，对象走 JSON，`null` 走 `sendNoContent`（204）。想发纯文本要自己设 header，或别把字符串当默认合同。

## 踩过的坑

1. **把 h3 当成带 listen 的框架**：核心包没有 `app.listen`。听端口是 [[listhen]] 或 Node `http` 的事。

2. **把 npm `latest` 当成 1.x**：当时 `latest` 是 `2.0.1-rc.29`。1.x 在 dist-tag `1x`。本页只绑定 1.15.11。

3. **以为 router 未命中就是 404**：默认不是。要立刻失败得开 `preemptive`。

4. **对 GET 调 `readBody`**：`assertMethod` 只放行 PATCH/POST/PUT/DELETE，GET 会抛错。

5. **把 `toWebHandler` 写成稳定 Web 入口**：源码标 experimental，并且仍经 Node mock。

## 适用 vs 不适用场景

**适用**：

- 已经或准备接到 Nitro / 自建 Node listener，需要一个 event 合同而不是完整框架
- 要把 Connect / Express 风格中间件用 `fromNodeMiddleware` 嵌进同一 stack
- 需要和 [[listhen]] 组成“应用 + 听端口”两件套

**不适用**：

- 想要开箱 `app.listen()`、内置 schema 编译或多 runtime `fetch` 预设——那是 [[fastify]] / [[hono]] 的合同
- 要跟踪 h3 2.x 重写线；本页明确停在 1.15.11
- 需要本轮未测的吞吐或 bundle 数字来做选型

## 学到什么

1. **h3 卖的是 event 和 stack，不是服务器进程**——听端口是另一包的职责。
2. **返回 `undefined` 是“继续往下”，不是空响应**——空响应是 `null` / `sendNoContent`。
3. **路由器默认给后面的 layer 留门**——抢占是选项，不是默认。
4. **1.x 和 2.x RC 不能混写成“当前 h3”**——要看 dist-tag 和调用方依赖。
