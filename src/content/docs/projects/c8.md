## 是什么

c8 是一个**不改写你的源码**的覆盖率 CLI。日常类比：它不像在试卷上先盖透明复写纸再答题，而是让引擎自己记“这道题有没有翻开”，考完再把记分册翻译成 Istanbul 能读的报表。

```js
// 你的测试照常跑；c8 只是在外面套一层
// npx c8 --reporter=text node --test
```

固定 `12.0.0` 的入口 `bin/c8.js` 做三件事：可选清空临时目录、把 `NODE_V8_COVERAGE` 指到该目录、用 `foreground-child` 拉起你的命令。子进程退出后，再读 V8 JSON、经 `v8-to-istanbul` 转成 Istanbul map，最后用 `istanbul-reports` 出报告。

## 为什么重要

不理解 c8 和 [[nyc]] 的分工，就很难解释：

- 为什么 `c8 mocha` 不必先用 Babel 插桩，也能出和 nyc 一样的 text / lcov
- 为什么默认覆盖率只统计**引擎真正加载过的文件**
- 为什么 `--all` 不是“再 require 一遍”，而是合成一份 count 为 0 的空报告
- 为什么 Node 版本写着 `^20.19.0 || ^22.12.0 || >=23`

## 核心要点

固定源码的主链可以拆成五步：

1. **拆参数**：`hideInstrumenteeArgs()` 只把子命令之前的参数交给 c8；`hideInstrumenterArgs()` 再把子命令及其后参数原样交给子进程。

2. **准备 V8 目录**：`clean` 默认 `true`。未设 `NODE_V8_COVERAGE` 时，临时目录落到 `reportsDir/tmp`，默认报表目录是 `./coverage`。

3. **原样执行**：设置环境变量后 `foregroundChild(...)`。c8 不 hook `require`，也不改 AST。

4. **合并 V8 JSON**：同步路径用 `@bcoe/v8-coverage` 一次 merge；`--merge-async` 则逐文件增量 merge，避免大套件 OOM。`file://` 会转成本地路径；`node:` 内建模块会被改写成 `*.js` 后再过滤。

5. **转 Istanbul 并出报告**：每个 script 走 `v8-to-istanbul`，再 `istanbul-lib-coverage` merge。默认 reporter 是 `text`。`--check-coverage` 默认关；阈值默认 lines 90、functions/branches/statements 0。

## 实践示例

### 案例 1：给 Node 测试套一层原生覆盖率

```bash
mkdir c8-toy && cd c8-toy
npm init -y
npm i -D c8@12.0.0
```

`sum.js` / `sum.test.js` 写完后：

```bash
npx c8 --reporter=text node --test
```

子进程看到的是原文件。覆盖率来自 V8 写进 `coverage/tmp` 的 JSON，不是 `__coverage__` 全局变量。

### 案例 2：`--all` 只补空报告，不加载源码

```bash
npx c8 --all --src src --reporter=text node --test
```

`Report._includeUncoveredFiles()` 给还没出现在 V8 结果里的文件合成 `functionName: '(empty-report)'`、`count: 0` 的区间。它**不会** `require` 这些文件。未加载文件因此按 0% 进入汇总。

### 案例 3：`--100` 只在报告阶段展开

```bash
npx c8 --100 node --test
```

`parse-args.js` 里把 `--100` 做成 yargs middleware 的代码仍是 TODO。真正改阈值的是 `lib/commands/report.js`：把 lines/functions/branches/statements 都写成 100，并打开 `checkCoverage`。只跑子命令、不走 `outputReport` 时，不要假定这个快捷方式已经生效。

## 踩过的坑

1. **把 c8 想成插桩器**：固定实现不改源码。没被 Node 加载的文件默认不会出现；要计入它们必须 `--all`。

2. **以为默认 threshold 四项都是 90**：只有 `lines` 默认 90，其余三项默认 0。没开 `--check-coverage` 时这些数字只是备用阈值。

3. **把 `--all` 理解成“执行未测文件”**：源码合成空 V8 记录，副作用、顶层 IO 都不会跑。

4. **忽略 `omitRelative`**：默认 `true`，非绝对路径（例如部分内部模块名）会被丢掉。

5. **把 Monocart 当成内置报告器**：`--experimental-monocart` 要可选 peer `monocart-coverage-reports@^2`；缺包会 `process.exit(1)`。

## 适用 vs 不适用场景

**适用**：

- 现代 Node 测试（`node --test`、[[jest]]、[[vitest]]）只想统计引擎真正执行过的代码
- 需要 Istanbul reporter 生态，但不想再走 AST 插桩
- 满足当前 engines：`^20.19.0 || ^22.12.0 || >=23`

**不适用**：

- 必须在加载前改写源码、或依赖 `global.__coverage__` 的旧工具链——那是 [[nyc]] 的范围
- 需要默认 `excludeAfterRemap: true` 的 Istanbul CLI 行为；c8 这项默认是 `false`
- 不能接受“只覆盖已加载文件”这条 V8 合同，又拒绝使用 `--all`

## 学到什么

1. **覆盖率可以不插桩**——V8 先记执行，CLI 再翻译报表。
2. **“全部文件”必须看实现**——`--all` 补的是空记录，不是二次执行。
3. **阈值默认不对称**——lines 90，其余 0；不要用 nyc 经验外推。
4. **快捷开关要看落地位置**——CLI 有 `--100`，源码却把展开留在报告阶段。

## 应用型自测

1. `c8 node --test` 会在跑测试前改写 `require` 到的源码吗？
2. 未设置 `NODE_V8_COVERAGE` 时，默认临时目录在哪？
3. `--all` 会把未测文件 `require` 进当前进程吗？

检查点：

1. 不会。固定入口只设 `NODE_V8_COVERAGE` 并 `foregroundChild`。
2. `reportsDir/tmp`，默认即 `./coverage/tmp`。
3. 不会。它合成 `count: 0` 的空 V8 报告。
