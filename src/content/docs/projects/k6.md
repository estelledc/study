## 是什么

k6 是 Grafana 维护的负载测试器：你用 JavaScript 写“虚拟用户做什么”，Go 进程负责调度并发、发协议请求、汇总指标。日常类比：剧本是 JS，导演和场务是 Go。

```js
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 10,
  duration: '30s',
  thresholds: {
    http_req_failed: ['rate<0.01'],
    http_req_duration: ['p(95)<800'],
  },
};

export default function () {
  const res = http.get('https://example.com/health');
  check(res, { 'status is 200': (r) => r.status === 200 });
  sleep(1);
}
```

`k6 run script.js` 走 `cmd.Execute()` → `internal/cmd`。`check` / `sleep` 来自内置模块 `k6`，不是 `k6/check`。脚本跑在 **sobek**（Grafana 维护的 JS VM）里，不开 Node。

## 为什么重要

不理解固定 2.2.0 的 shortcut → scenario → executor 链，就解释不了下面几件事：

- 为什么只写 `vus` + `duration` 时，实际跑的是 `constant-vus`
- 为什么 `check` 失败不会让进程退出，而 `thresholds` 会
- 为什么 `p95<500` 不再是“悄悄忽略”，而是解析失败
- 为什么浏览器协议现在直接 `import … from 'k6/browser'`，不必再 `xk6 build`

## 核心要点

固定 2.2.0 的主链可以拆成五步：

1. **入口与模块**：`main` 只调用 `cmd.Execute()`。稳定 JS 模块登记在 `internal/js/jsmodules.go`，包括 `k6`、`k6/http`、`k6/browser`、`k6/net/grpc`、`k6/ws`、`k6/websockets`。`k6/experimental/browser` 已移除。

2. **把短选项收成 scenario**：`DeriveScenariosFromShortcuts` 规定互斥规则。`iterations` → `shared-iterations`；单独的 `duration` → `constant-vus`；`stages` → `ramping-vus`；什么都不写则默认 1 VU / 1 次 `per-vu-iterations`。`duration` 与 `stages`、`scenarios` 不能同时出现。

3. **executor 调度 VU**：本修订注册六种 executor：`constant-vus`、`ramping-vus`、`shared-iterations`、`per-vu-iterations`、`constant-arrival-rate`、`ramping-arrival-rate`。v2 已删除 `externally-controlled`，脚本里再写会启动失败。

4. **VU 迭代跑 default 函数**：每个 VU 在 sobek 里循环执行 `export default`。`http.get` 走每 VU 一份 `k6/http` 客户端。`sleep` 用 Go timer，可被取消。VU 之间没有自动思考时间。

5. **check 软记、threshold 硬判**：`check()` 禁止在 init context 使用；失败只把 `Checks` 指标记成 0，返回 `false`，不中止迭代。`thresholds` 必须写成 `p(95)<800` 这种 `方法 运算符 数值`；`Parse()` 填 `parsed`，非法表达式直接报错。

## 实践示例

### 案例 1：`vus` + `duration` 就是 constant-vus

```js
export const options = { vus: 50, duration: '1m' };
```

`DeriveScenariosFromShortcuts` 生成名为 `default` 的 `constant-vus`。`constant-vus` 要求 VU > 0，且 duration 至少 1 秒。

### 案例 2：stages 走 ramping-vus，threshold 用 p(n)

```js
export const options = {
  stages: [
    { duration: '30s', target: 50 },
    { duration: '1m', target: 200 },
    { duration: '30s', target: 0 },
  ],
  thresholds: {
    http_req_failed: ['rate<0.01'],
    http_req_duration: ['p(95)<800'],
  },
};
```

顶层 `stages` 被收成 `ramping-vus`。百分位只接受 `p(0)`–`p(100)`，含小数如 `p(99.9)`。

### 案例 3：把样本推给 Prometheus remote write

```bash
k6 run --out experimental-prometheus-rw=http://prom:9090/api/v1/write script.js
```

`experimental-prometheus-rw` 仍是内置 output 名。本轮未连 Prometheus，也未核对看板数字。

## 踩过的坑

1. **把 k6 当成 Node**：不能 `import lodash`。要用 `k6/encoding`、`k6/crypto` 等内置模块，或走 `k6/x/…` 扩展。扩展由 xk6 / 依赖约束装配，不是 npm。

2. **`import { check } from 'k6/check'`**：2.2.0 没有这个模块。正确写法是 `import { check, sleep } from 'k6'`。

3. **写 `p95<500` 当 threshold**：解析器要求 `p(` 与 `)`。`p95` 会 `failed parsing method from expression`，测试启动失败；不是旧印象里的“假绿”。

4. **以为 check 失败等于 CI 失败**：check 只推 `Checks` 样本。要让 `k6 run` 非 0 退出，得写 `thresholds`。

5. **还在用 `k6/experimental/browser` 或本地重编 xk6-browser**：本修订里 browser 已毕业为 `k6/browser`；旧实验路径会抛移除错误。

6. **把 star 数、单机 VU 上限或“开源第一”当成本轮事实**：这些未在固定提交里测量。

## 适用 vs 不适用场景

**适用**：

- HTTP / gRPC / WebSocket 的脚本化负载，并且要把选项收成可 review 的 JS
- CI 里用 threshold 当硬门，而不是只看 check 百分比
- 需要内置 `k6/browser` 做协议级浏览器步骤，并能接受 Chromedp 这条链

**不适用**：

- 必须用 Node 生态或 Python 写复杂业务剧本——看 [[locust]]
- 测试人员只接受 GUI、不写脚本——看 [[jmeter]]
- 还依赖 `externally-controlled`、`k6 pause` / `k6 scale` 运行时改 VU——v2 已删除
- 不能接受脚本跑在 sobek 而不是 Node

## 学到什么

1. **短选项不是另一套引擎**——`vus`/`duration`/`stages`/`iterations` 只是 scenario 的语法糖，最终都进 executor 表。
2. **check 和 threshold 分工不同**——一个记软断言样本，一个解析表达式并影响退出码。
3. **VU 没有默认思考时间**——要间隔就显式 `sleep`，否则迭代会立刻接下一次。
4. **v2 收紧了运行时控制面**——browser 进稳定模块，`externally-controlled` 被拿掉。

## 应用型自测

1. 只写 `export const options = { vus: 10, duration: '30s' }`，会生成哪种 executor？
2. `import { check } from 'k6/check'` 在 2.2.0 能解析到内置模块吗？
3. threshold 写成 `http_req_duration: ['p95<500']` 会被忽略还是启动失败？

检查点：

1. `constant-vus`。`DeriveScenariosFromShortcuts` 在有效 `duration` 且没有 `stages`/`scenarios` 时走这条。
2. 不能。`check` 挂在模块 `k6` 的 named export 上。
3. 启动失败。`parseThresholdAggregationMethod` 只接受 `p(…)`，不接受 `p95`。
