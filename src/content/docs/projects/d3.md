## 是什么

D3（**D**ata-**D**riven **D**ocuments）是一组把数据接到网页标准上的可视化原语，不是“选数据→选图表”的成品库。日常类比：[[chart-js]] 给你客厅模板，d3 给你砖、尺和路径模具——更费力，但能拼非标准图形。

固定 `d3@7.9.0` 的 `src/index.js` 只做一件事：把 30 个独立模块 `export *` 到同一个命名空间。selection / scale / shape 的实现分别在 lockfile 解析到的 `d3-selection@3.0.0`、`d3-scale@4.0.2`、`d3-shape@3.2.0`。

```js
import {scaleLinear} from "d3-scale"
const x = scaleLinear().domain([0, 100]).range([0, 800])
x(50) // → 400
```

这一行把数据域映射到像素域。`x` 既是函数也是配置对象。

## 为什么重要

不按固定模块读 d3，下面这些事很容易写错：

- 为什么 [[observable-plot]] / [[visx]] / [[recharts]] / [[nivo]] 常吃 d3 的 scale、shape 或 hierarchy，而不是另写一套映射
- 为什么 `d3.select` 会碰 `document`，而 `scaleLinear` / `line` 可以当纯函数用
- 为什么数组中间插入元素时，不传 key 的 data join 会让后续节点错位
- 为什么 `d3.pie()` 返回的是角度描述，不是 SVG `d` 字符串

## 核心要点

固定版本可以拆成四层：

1. **Umbrella 再导出**：`d3` 包自己几乎没有算法；`test/d3-test.js` 断言每个依赖的 named export 都出现在 `d3` 上。

2. **Selection + data join**：`select` 用 `document.querySelector`。`data(value, key)` 把值写到 `node.__data__`；无 key 按索引配对，有 key 用 `Map`。`join(name)` 对 enter 做 `append`，对未给出的 exit 默认 `remove`，再 `merge` + `order`。

3. **Scale**：`scaleLinear` 建立在 continuous transformer 上，再挂 `ticks` / `nice`。`clamp` 默认关闭；`invert` 用数值插值反解。默认 `interpolate` 来自 `d3-interpolate`，颜色字符串可以走同一条通道。`d3-scale@4.0.2` 还导出 log/time/band/ordinal 以及 sequential/diverging 变体，不能再数成“一共 13 种”。

4. **Shape**：`line()` 默认用 `d3-path` 缓冲成字符串；设置 `context` 后改为向 Canvas-like 接口推点。`pie()` 只算 `startAngle` / `endAngle`，path 要再交给 `arc()`。

## 实践示例

### 案例 1：`join` 一次处理 enter / update / exit

```js
svg.selectAll("circle")
  .data([10, 20, 30, 40], (d) => d)
  .join("circle")
  .attr("cx", (d) => d * 10)
  .attr("cy", 50)
  .attr("r", 5)
```

`data()` 先按 key 分成三类；`join("circle")` 把 enter 建成 `circle`，并把 update 合并回去。第二次用更短的数组再跑同一段，没有对应数据的节点会被默认 `remove`。

### 案例 2：`scaleLinear` 的 clamp 与 invert

```js
const x = scaleLinear().domain([0, 100]).range([40, 780]).clamp(true)
x(50)        // 线性插值
x.invert(410)
x(999)       // clamp 后停在 range 端点
```

不设 `clamp` 时，域外输入会按同一斜率外推。`invert` 走数值插值，不是颜色插值。

### 案例 3：只用纯函数，DOM 交给 React

```jsx
function LineChart({data}) {
  const x = scaleLinear().domain([0, 100]).range([0, 800])
  const y = scaleLinear().domain([0, 1]).range([400, 0])
  const path = line().x((d) => x(d.t)).y((d) => y(d.v))(data)
  return <svg width={800} height={400}><path d={path} fill="none" stroke="currentColor" /></svg>
}
```

`scale` 与 `line` 在固定源码里都不碰 DOM。这是 visx / Recharts 常见的拆法：d3 负责映射，框架负责提交。

## 踩过的坑

1. **不传 key**：默认按索引绑 `node.__data__`。数组中间插入时，后续节点会拿到别人的数据。
2. **把 umbrella 当实现仓**：读 `d3/d3` 的 `src/` 看不到 join / scale 算法；要以 lockfile 子包为准。
3. **`import * as d3` 再期望自动 tree-shake**：umbrella 会再导出全部 30 个模块；要变小应直接从 `d3-scale` / `d3-shape` 取 named export，并以目标 bundler 实测为准。
4. **和 React 抢同一片 DOM**：`d3-selection` 会自己 `append` / `remove`。要么 React 只给空容器，要么只用纯函数部分。
5. **把 `pie()` 当 path 生成器**：它返回角度描述；没有 `arc()` 就没有 `d` 属性。

## 适用 vs 不适用场景

**适用**：
- 非标准图形、数据新闻、需要自己拼轴 / tooltip / 图例
- 只要 scale / shape / hierarchy / force 这些纯函数
- 能接受 selection 直接写 DOM 的 notebook 或原生页面

**不适用**：
- 标准 dashboard 折线 / 柱 / 饼 → [[chart-js]] / [[echarts]] / [[recharts]]
- 需要现成 Chart 抽象和主题 → [[observable-plot]]
- 必须纯 SSR、又没有 DOM polyfill → 不要走 `d3-selection`
- 把固定性能数字当选型依据 → 本文没有跑 SVG/Canvas/WebGL benchmark

## 固定版本边界

## 学到什么

1. **可视化的核心合同是数据 → 视觉通道**，不是“图表类型枚举”
2. **umbrella 包版本 ≠ 实现包版本**，要同时核对 lockfile
3. **函数即对象**让 `x(50)` 和 `x.domain([...])` 共用一个值
4. **state 可以挂在 DOM 上**：`node.__data__` 是 join 能重跑的前提
5. **path 字符串和 DOM 提交是两件事**：shape 可以脱离 selection 单独测

## 应用型自测

1. `selectAll("circle").data(arr).join("circle")` 没传 key。往 `arr` 中间插一项，原有 circle 会按身份留下吗？
2. 只调用 `d3.pie()(values)`，不调用 `d3.arc()`。拿得到 SVG path 吗？
3. `scaleLinear().range(["red", "blue"])(0.5)` 依赖哪一层默认插值？它等于手写 RGB 混合吗？

检查点：

1. 不会。无 key 时按索引重绑，中间插入会让后续节点拿到新数据。
2. 拿不到。`pie` 只返回角度描述，path 由 `arc` 另算。
3. 走 continuous 的默认 `d3-interpolate`；具体颜色空间与字符串结果要以该插值实现为准，不能口算成固定 `"rgb(128, 0, 128)"`。
